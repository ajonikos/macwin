# Фаза 1: отчёт

## Что сделано

- **Буфер обмена (текст).** Изменения буфера проверяются каждые 250 мс в отдельном потоке и передаются на другую машину. Каждое обновление идёт своим QUIC-потоком с низким приоритетом, поэтому большой текст не задерживает мышь и heartbeat. Лимит по умолчанию 4096 КБ, максимум 16 МБ.
  - Порядок задаёт часы Лэмпорта. При одновременном копировании обе машины сходятся на одном тексте, это проверено property-тестом на 20 000 случайных сценариев.
  - Эхо исключено трижды: счётчик изменений после своей записи, маркер `io.macwin.origin` и хеш общего текста.
  - Не передаются: пароли из менеджеров паролей (`org.nspasteboard.Concealed/Transient`, Windows `ExcludeClipboardContentFromMonitorProcessing`, `CanUploadToCloudClipboard=0`), картинки и файлы, слишком большой текст.
  - Содержимое буфера никогда не пишется в лог.
  - Буфер работает, только если его включили обе машины.
- **Сопряжение по коду (SPAKE2).** Одна машина показывает 6-значный код, на другой его вводят.
  - Используется отдельный ALPN `macwin-pair/1`. Отпечатки обоих сертификатов и TLS exporter входят в SPAKE2 и в подтверждение ключа, так что MITM без кода не пройдёт.
  - Каждая попытка проверяет не больше одного варианта кода. После неудачи код сгорает и выдаётся новый; всего 5 попыток за 10 минут.
- **Ключ в Keychain / DPAPI.**
  - macOS: login keychain, запись `io.macwin.MacWin` / `identity`.
  - Windows: `identity.dpapi` в `%APPDATA%\macwin`, зашифрованный DPAPI на текущего пользователя.
  - `MACWIN_KEY_STORE=file` хранит ключ в файле `identity.secret` с правами 0600.
  - Старые PEM-файлы фазы 0 переносятся в хранилище автоматически, с проверкой, и затем удаляются.
- **Конфиг** `config.toml`: listen, remap, clipboard, peer (отпечаток, имя, ОС, сторона, адрес). Неизвестные ключи считаются ошибкой.
- **Команды:**
  - `macwin pair`;
  - `macwin pair HOST --code CODE [--side]`;
  - `macwin unpair`;
  - `macwin config show|set`;
  - `macwin run`: сеанс по конфигу с автопереподключением (1 → 10 с, таймаут дозвона 5 с). Машина, которая дозванивалась при сопряжении, дозванивается и дальше; вторая слушает.
- **Имя Mac** теперь берётся из «Имя компьютера» (раньше было `unknown`).

## Найденная ошибка фазы 0b (исправлена)

`spawn_session` уничтожал бэкенд перехвата при выходе из функции, а `MacCapture`/`WinCapture` при уничтожении останавливают свой поток. Из-за этого в `spike kvm` перехват умирал сразу после подключения, и переход курсора на другую машину не работал бы.

Теперь бэкенд принадлежит задаче сеанса. Это закреплено регрессионным тестом, а фейковый бэкенд ведёт себя при уничтожении как настоящий. Заодно разорван цикл ссылок Core → control → sink → Core, из-за которого после сеанса оставались занятыми соединение и порт.

## Ручной тест

1. Mac: `scripts/macos/bundle.sh`, затем `scripts/macos/run.sh identity`.
   - Должно быть `key: login keychain, item "io.macwin.MacWin" / "identity"`.
   - Если раньше запускался голый `target/release/macwin`, macOS может спросить доступ к связке: «Разрешать всегда».
   - Разрешения из 0b (Универсальный доступ, Мониторинг ввода) должны сохраниться.
2. PC: скопировать `target/x86_64-pc-windows-gnu/release/macwin.exe`, затем `.\macwin.exe identity`. Должно быть `key: DPAPI-encrypted file ...\identity.dpapi`.
3. PC (PC справа от Mac): `.\macwin.exe pair --side left`. В окне брандмауэра разрешить частные сети. PC покажет код и готовую команду.
4. Mac: `scripts/macos/run.sh pair <IP PC>:47800 --code <код>`. Разрешить «Локальная сеть». Ожидается `paired with "<имя PC>"` и `its screens are on the right of this machine`.
   - Дополнительно: ввести неверный код. PC должен показать новый код, а повтор с новым кодом должен пройти.
5. PC: `.\macwin.exe run`, Mac: `scripts/macos/run.sh run`. Проверить:
   - переход курсора через правый край Mac и обратно;
   - Cmd+C на Mac, затем Ctrl+V на PC, и наоборот (кириллица, длинный текст);
   - копирование пароля из менеджера паролей не попадает на другую машину;
   - картинка не передаётся и не ломает текст, скопированный следом;
   - Ctrl+C в окне PC, затем снова `run`: Mac переподключается сам (в логе `connecting to`, `connected to`);
   - Control+Option+Shift+Esc на Mac и Ctrl+Alt+Shift+Esc на PC: `run` останавливается, ввод локальный.
6. По желанию: `cargo test -p macwin-platform-macos -- --ignored keychain`. Тест создаёт и удаляет запись `io.macwin.test`.

## Известные ограничения

- При подключении буферы не синхронизируются: передаются только изменения после соединения.
- Только текст. Картинки и файлы придут с передачей файлов.
- IP другой машины вводится один раз при сопряжении, автопоиска в сети пока нет.
- Внутри MacWin.app нет ввода с клавиатуры в терминал, поэтому код передаётся через `--code`.
- На новых macOS чтение буфера может показывать запрос «Вставка из других приложений». MacWin нужно разрешить один раз.
- Остаются известные мелочи из 0b: прокрутка на Mac пока построчная, Caps Lock при инжекте, не проверено направление горизонтальной прокрутки.
